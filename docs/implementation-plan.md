# План реализации

## Этап 0 — checkpoint исследования

- Цель: зафиксировать завершённое исследование API.
- Входные зависимости: текущий репозиторий и документация исследования.
- Результат: checkpoint commit и tag.
- Готово, когда: история Git содержит проверяемую точку возврата.
- Не реализуется: перенос кода, инфраструктура, продуктовые функции.

## Этап 1 — каркас приложения

- Цель: создать npm workspace, NestJS skeleton, health endpoint, пакет eQuGPS, конфигурацию и безопасное управление session token.
- Входные зависимости: этап 0.
- Результат: `apps/api`, `apps/web`, `packages/equgps`, `packages/shared` и минимальный health API.
- Готово, когда: backend запускается, health endpoint проверяется, токены остаются только в памяти.
- Не реализуется: БД, UI, polling.

## Этап 2 — хранение данных

- Цель: Docker Compose, PostgreSQL, Prisma, базовые таблицы и миграция.
- Входные зависимости: этап 1.
- Результат: воспроизводимая локальная БД и схема данных.
- Готово, когда: миграции применяются на пустой БД.
- Не реализуется: Redis, PostGIS, историческое хранилище всех точек.

## Этап 3 — fleet и dashboard backend

- Цель: fleet API, dashboard backend и кэш дневных показателей.
- Входные зависимости: этапы 1–2 и адаптеры источников.
- Результат: нормализованные данные парка для UI.
- Готово, когда: API выдаёт безопасные агрегаты и источник данных.
- Не реализуется: frontend, Telegram, PDF/XLSX.

## Этап 4 — web-интерфейс

- Цель: Next.js, адаптивный dashboard и страница машины.
- Входные зависимости: этап 3.
- Результат: UI списка, деталей и маршрута.
- Готово, когда: основные сценарии работают на мобильной и desktop ширине.
- Не реализуется: роли, автоматические уведомления, отчёты.

## Этап 5 — Telegram и настройки

- Цель: grammY-бот, настройки и тестовое уведомление.
- Входные зависимости: этапы 1–2.
- Результат: изолированный `telegram` модуль и сохранённые настройки.
- Готово, когда: тестовое сообщение отправляется через интерфейс модуля.
- Не реализуется: polling нарушений и ежедневные отчёты.

## Этап 6 — позиции и нарушения

- Цель: polling последних позиций, выявление превышений, дедупликация, городская геозона Винницы.
- Входные зависимости: этапы 2–5.
- Результат: сохранённые нарушения и уведомления без повторов.
- Готово, когда: правила и дедупликация покрыты тестами.
- Не реализуется: полное сырое GPS-хранилище, PostGIS.

## Этап 7 — отчёты

- Цель: PDF/XLSX, ручные отчёты и автоматический ежедневный отчёт.
- Входные зависимости: этапы 3–6.
- Результат: отчёты по одной машине, выборке и парку.
- Готово, когда: документ формируется и доставляется через `telegram` интерфейс.
- Не реализуется: webhook Telegram, сложные шаблоны BI.

## Этап 8 — production readiness

- Цель: пользовательская авторизация, роли `ADMIN` и `MANAGER`, production deployment, backup и monitoring.
- Входные зависимости: этапы 1–7.
- Результат: защищённый развёртываемый сервис.
- Готово, когда: проверены backup/restore, мониторинг и разграничение ролей.
- Не реализуется: микросервисная декомпозиция.
