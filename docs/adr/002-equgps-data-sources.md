# ADR 002: разделение источников eQuGPS

- Статус: принято.
- Контекст: исследованы официальный API `trace.equgps.com` и отдельный недокументированный web API `gps.equgps.com`.

## Решение

Официальный и web API реализуются отдельными адаптерами внутри модуля `equgps`. Прикладные модули получают нормализованные данные через интерфейсы адаптера.

## Причины

Web API недокументирован, использует отдельные transport-структуры и может меняться. Его нельзя напрямую использовать во всём приложении: это распространит нестабильные контракты, session token и детали fallback по бизнес-модулям.

`/reports/route` и `/reports/summary` официального API исключаются из MVP как ненадёжные. Стратегия деградации: `/runs` → `mode1`; `mode1` → приблизительный расчёт по historical positions; `mode2` → ранее сохранённые нарушения; `routes-new` → historical positions.

## Последствия

Каждый ответ содержит информацию об источнике и деградации. Транспортные форматы и токены не проходят за границу адаптера.
