# ADR 003: управление session token eQuGPS

- Статус: принято.
- Контекст: `POST /session` официального API возвращает token, который подтверждённо принимается web API.

## Решение

Backend получает token через `POST /session` с email/password и хранит его только в памяти процесса. Refresh реализуется как single-flight: одновременно выполняется только один `POST /session`, параллельные запросы ожидают тот же результат. При `401` или `403` каждый исходный read-only запрос повторяется после refresh максимум один раз.

## Ограничения безопасности

- token не записывается в файл, PostgreSQL или audit;
- token, учётные данные, query URL с token и заголовки авторизации не логируются;
- `EQUGPS_WEB_TOKEN` остаётся только диагностическим fallback;
- token создаётся и используется только адаптером `equgps`.

## Последствия

После перезапуска backend создаёт новую сессию по необходимости. Single-flight и политика одного повтора предотвращают шторм session-запросов и бесконечные повторы при ошибке доступа.
