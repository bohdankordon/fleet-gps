# ADR 003: управление session token eQuGPS

- Статус: принято.
- Контекст: `POST /session` официального API возвращает token, который подтверждённо принимается web API.

## Решение

Backend получает token через `POST /session` с email/password и хранит его только в памяти процесса. При `401` или `403` допускается один refresh token и один повтор прикладного read-only запроса.

## Ограничения безопасности

- token не записывается в файл, PostgreSQL или audit;
- token, учётные данные, query URL с token и заголовки авторизации не логируются;
- `EQUGPS_WEB_TOKEN` остаётся только диагностическим fallback;
- token создаётся и используется только адаптером `equgps`.

## Последствия

После перезапуска backend создаёт новую сессию по необходимости. Политика одного refresh предотвращает бесконечные повторные запросы при ошибке доступа.
